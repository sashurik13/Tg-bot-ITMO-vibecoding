# Проверка лабораторной №1 перед защитой

Автоматические проверки не используют реальных пользователей и вызовы LLM. Демонстрация в Telegram выполняется отдельно: не показывайте `.env`, ключи, пароли или полные журналы SDK на экране.

## Запуск и проверки

1. Запустить Docker Desktop.
2. Выполнить `powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start.ps1 --setup-only`. Скрипт подготавливает окружение, БД и применяет миграции.
3. В PyCharm выбрать интерпретатор `.venv` и запустить модуль `app` из корня проекта. Запускать один polling-процесс на токен.
4. Запустить Ruff, format check и pytest по README. Для настоящей PostgreSQL включить `RUN_INTEGRATION=1`; тесты создают и удаляют только свою БД.

## Пользователь А

| Действие | Что проверить |
| --- | --- |
| `/start` | Справка со всеми командами |
| `/study`, затем «Объясни цикл while в Python» | Содержательное объяснение и статус «печатает» |
| «А как остановить этот цикл?» | Учёт предыдущего вопроса |
| `/settings`, `/settings 0.7`, `/settings` | Видны режим и модель; temperature изменилась |
| `/settings 0.5`, `/settings` | Отказ; осталось 0.7 |
| `/translate`, затем «Переведи: Хорошего дня!» | Уточнение языка; учебный диалог очищен |
| «На английский» | Перевод исходной фразы без пояснений |
| `/plan`, затем «Помоги подготовиться к экзамену» | Уточняющий вопрос |
| «Сегодня 13 ноября, экзамен 20 ноября; 4 темы и час в день» | План по заданным фактам, приоритеты, риски и действия; нет обещания уведомлений |

## Два пользователя и перезапуск

У пользователя Б выбрать `/study` и `/settings 1.0`, задать другую тему. У А сохранить собственную настройку и тему. Перезапустить приложение без удаления volume БД: продолжение каждого диалога должно учитывать только его историю; `/settings` должен восстановить разные значения.

У А вызвать `/reset`: режим и temperature сохраняются, история очищается. У Б продолжить прежнюю тему: его история остаётся. Повторить со сменой режима у А. Для сброса во время генерации отправить вопрос и `/reset`: очистка выполняется после завершения ответа.

## Ошибки и длинный ответ

Контролируемые fake-сценарии уже есть в `tests/test_llm.py`, `tests/test_telegram.py`, `tests/test_modes.py`: таймаут, авторизация, сеть, HTTP 503/429, пустой и неполный ответ, несколько частей Telegram и частичная доставка. На защите можно запустить конкретный тест, не портя настоящий ключ и не меняя настройки рабочего бота.

## Эксперимент и сдача

Выбрать одну поддерживающую temperature модель, выполнить `scripts.experiment` по README и заполнить отчёт только реальными результатами. При запуске в Telegram перед каждым из 12 запросов вызвать `/reset`; режим и вопрос одинаковы, меняется только temperature. Сравнение двух инструкций выполнять при одинаковой модели, настройках и пустой истории.

После завершения сохранить код, отчёт и результаты в Git, создать тег `lab1`. Не ставить сдаваемый тег на незаполненный эксперимент и не публиковать секреты.
